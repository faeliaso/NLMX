# ADR 0017 — DOCX and XLSX: indexed and cited, without a viewer

- Status: accepted
- Date: 2026-10-04
- Addresses: RF01 (import more formats). Extends ADRs 0011–0016; does not supersede any.

## Context
The multi-format architecture already indexes, retrieves and cites any `DocumentType`; only PDF has a viewer. The most common office formats were missing: Word (DOCX) and Excel (XLSX).

## Decision
- **Two new `DocumentType`s** (`docx`, `xlsx`), never `previewable` nor `is_paged`: there is no DOCX Viewer, Excel Viewer or preview. A DOCX/XLSX source opens the **Informações da fonte** (Source information) panel (ADR 0016); `Citation::viewer_target` is `None`.
- **One crate, two parsers** — `crates/adapters/parser-office` (`DocxDocumentParser`, `XlsxDocumentParser`), using only `zip` + `quick-xml`, already used by `parser-epub` (no `calamine`/`docx-rs`). Same zip-bomb limits (entries, bytes per entry, total bytes). Password-protected file (CFB container; also old `.doc`/`.xls`) → `ParseError::Encrypted`.
- **DOCX** → sections by heading (`Heading 1..9`, `Título N`, structure level or derived style), blocks `Paragraph`/`ListItem`/`Table`. Location `SourceLocation::Docx { heading_path, paragraph_start, paragraph_end, table }`; label with the section only (`Manual.docx · Arquitetura › Backend`, and `… › Frontend, tabela 1` (table 1) when the chunk includes a table) — the paragraph range is kept in the location but outside the label, and there is no page. `table` is optional in the JSON (no migration); on merge, a chunk that includes a single table names it and one that mixes two names none. Headers, footers, notes, comments and deleted text (change tracking) are not read.
- **DOCX tables** → one `Record` per data row, in the text `Tabela 1 — <caption, if the previous paragraph is Legenda/Caption>: Nome | Cidade | Cargo\nNome: João\nCidade: Fortaleza\nCargo: Engenheiro` (the first line of each chunk already says it came from a table and what the columns are; the structural kind `Record` stays in the `ParsedDocument`, with no new field in `ChunkMetadata`). Each row is atomic in the generic chunker and has its own paragraph number. Header = first marked row (`w:tblHeader`/`w:tblLook firstRow`) or, without a mark, a row of short, non-empty, distinct cells; without a reliable header (or with 1 row) the table stays as a `Table` block of `a | b` rows, losing no content. Merged cells (`gridSpan`) keep the text in the first column; nested tables are flattened into the cell.
- **Hyperlinks and fields** → the displayed text is kept; the URL and field codes (`instrText`) are not indexed. **Encoding** → XML parts in UTF-16 or with a UTF-8 BOM are normalized to UTF-8; truncated UTF-16 is `Invalid`. Metadata (`docProps/core.xml`: title, author, subject, created/modified) is optional and never brings the parse down. `DOCX_VERSION` = 3.
- **XLSX** → one section per visible sheet; each row is a `Record` block (first row = header when it is all text and there is data; otherwise `Coluna N` (Column N) columns, with `NoHeaderRow`/`UncertainHeader`). Formula values are those cached in the file; dates become ISO text. Location `SourceLocation::Xlsx { sheet_index, sheet_name, row_start, row_end }` with the **Excel row number** (not "data row"), label with the sheet and the rows of the chunk (`clientes.xlsx · Clientes, linhas 2–3` (rows 2–3), like CSV/Markdown; `SourceLocation::Xlsx` is the representation of "rows of a sheet": sheet + start/end row, with no page or coordinates). If the sheet has an **Excel table** (`xl/tables`, `ref` + `headerRowCount`), the header and records are the table's and rows outside it (title, notes) become text rows `Linha N: a | b` (Row N: a | b) in the right place; without a table the verified-header rule applies. Repeated column names get a suffix (`Valor`, `Valor (2)`). Numbers are kept as the file stores them; `XLSX_VERSION` = 2. Hidden sheets are skipped (`SkippedUnit`). More than 250 thousand rows in total ⇒ `TooLarge`.
- **Chunking.** DOCX uses the generic core (like Markdown/EPUB). XLSX uses the CSV `RecordChunker`, generalized by `chunk_sheet`: one pass per sheet (own columns), preamble `Arquivo / Planilha / Colunas / Linhas` (File / Sheet / Columns / Rows), `section_path = [sheet]` and continuous indexes. CSV output does not change (`MultiFormatChunker::VERSION` and `RecordChunker::VERSION` stay).
- **Database.** Migration `0013_docx_xlsx`: the `CHECK` of `documents.format` did not accept the new names. Since SQLite cannot alter a `CHECK` and recreating `documents` would require handling all FKs, the column is **replaced** (copy into `format_next` with the new `CHECK`, drop the old one and rename), dropping and recreating `documents_touch`, `documents_format` and the generated column `previewable`; with the trigger dropped, no row changes `version`/`updated_at`. `down.sql` deletes DOCX/XLSX documents and restores the old `CHECK`. Sections, provenance and citations store the location as free JSON: no migration.

## Interface
Documentos, Indexação, chat sources and citations use `ui-web::formats::format_view` (Lucide-style icon, short label and description: "Documento do Microsoft Word" (Microsoft Word document), "Planilha do Microsoft Excel" (Microsoft Excel spreadsheet)). The **Informações da fonte** panel shows type, status, chunks, size, dates and "Usado em N conversas" (Used in N conversations) from the database; for XLSX also `Planilhas: N` (Sheets: N) (`SourceDetails.sheets` = indexed sections; hidden or empty sheets do not count). Neither has "Abrir no PDF", viewer or preview; clicking the source or `[n]` only selects and shows the panel. Import is the single flow (file picker built from the registered parsers); there is no drag and drop in the app.

## Library (`calamine`)
Evaluated and not adopted: it is not in the registry/lockfile (it would require network and ~10 transitive dependencies) and the in-house parser (zip + quick-xml, already used by EPUB/DOCX) reads only what the RAG needs, with the same zip-bomb limits and controlled errors. Reading is structured first (`Row`/`Cell` with Excel row and column number) and only then becomes `Record`s.

## Consequences
- Tests that used `.docx` as an "unknown format" now use `.odt`.
- `.doc` and `.xls` (pre-2007) are not supported; they arrive as `Encrypted`, which is the only way to tell them apart by their bytes.
- Out of v1: DOCX headers/footers/notes, images and charts, formulas without a cached value, merged XLSX cells (read as empty outside the first).
