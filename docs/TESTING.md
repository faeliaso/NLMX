# Testing strategy, metrics and logs

## Suites

| Target | What runs | Needs |
|---|---|---|
| `make test` | all tests (default) | `make bootstrap` (PDFium) |
| `make test-unit` | unit tests inside each crate (`--lib`) | — |
| `make test-integration` | crate integration tests (`crates/*/tests`: SQLite, PDFium, process fakes) + doc-tests | PDFium |

There are only unit and integration tests, plus `tests/tests/` (architecture rules, model activation) and `release_acceptance` (only via `make acceptance`, `#[ignore]`). `make test` runs all of that; there are no E2E, real-model, performance or benchmark suites.

## What each category covers

- **Unit**: pure functions and isolated components, for example:
  - domain: hybrid fusion, intents, `Measurement`, `find_in_spans`;
  - application: ContextBuilder, CitationEngine;
  - adapters: SSE parser, PDFium layout/rotation transforms;
  - telemetry: recording, redaction, rotation;
- **Integration**: each adapter against the real thing or a process fake, for example:
  - SQLite: reversible migrations, cascades, the `ConversationRepository` contract;
  - PDFium (`crates/adapters/pdf-pdfium/tests`);
  - `fake-llama-server`;
  - local HTTP server for downloads.

  The **port contracts** (`nlmx_testing::*_contract`) run against the fake and against the real adapter.
- **PDF**: fixtures generated by `examples/generate_fixtures.rs`:
  - text, scanned, mixed, report, copy, corrupted;
  - **password-protected** (Ghostscript), **rotated pages**, **accents in several fonts**, **200 pages** and **canary**.

  The tests check metadata, spans with coordinates, images, rendering, errors and rotation (boxes inside the displayed page, text found on rotated pages).
- **Vector Search**: sqlite-vec KNN with filters and reindexing, and **recall@10 ≥ 0.99** against exact cosine on 2,000 vectors with a fixed seed (`store-sqlite`).
- **RAG**: unit (context, citations, intents, follow-up).
- **IPC**: the Tauri command logic (`run_answer`, `run_cancel`) with fakes covers:
  - `token…done`;
  - duplicate generation (`running`);
  - cancellation with partial text;
  - `{ code, message }` errors.

  There is also a round trip through Tauri's test runtime (`tauri::test`) and tests of the `nlmx://` protocol (`src-tauri/src/protocol.rs`).
- **Model Manager** (`crates/adapters/models-catalog`):
  - catalog;
  - download with progress and checksum;
  - resume via Range;
  - cancellation;
  - insufficient disk;
  - corrupted file;
  - activation and removal;
  - update;
  - one download per model.

  Download **only with user confirmation**: a `compile_fail` doc-test (a `ConfirmedDownload` cannot be created without `confirm()`) and an architecture test (the only caller of `.confirm()` is the `download_model` command).

## Measurements

Recorded by `nlmx_application::telemetry::record(Measurement)`, a `tracing` event with target `nlmx::metrics`. The `domain::telemetry::Measurement` type only accepts ids, counts, durations and fixed labels, so **there is no way to record content**.

| Measurement | Source |
|---|---|
| import time, pages/s, chunks | `DocumentIngestion` (extraction, structure, chunks, save) |
| embeddings/s | `EmbedDocuments` |
| retrieval time (semantic, lexical, total) | `HybridRetriever` |
| generation time, 1st token, prompt tokens | `RagEngine` |
| error rate per operation | failures ÷ total (`*Failed` with `ErrorKind`) |
| memory (app RSS, `llama-server`, `fm serve`) | `nlmx-telemetry::sampler`, every 60 s and when opening Diagnóstico |
| storage (database + WAL, library, models, logs) | same, also after importing |

The `MetricsRegistry` (`crates/adapters/telemetry`) aggregates the session: counters, p50/p95/max, rates. It appears in **Configurações › Diagnóstico** (Settings › Diagnostics; with "Copiar diagnóstico", aggregates only) and in the `make bench` report.

## Structured logs

- `~/Library/Application Support/dev.nlmx.desktop/logs/nlmx.jsonl`: one JSON line per event, with `ts`, `level`, `target`, `message`, `fields` and `spans`. Rotates every 5 MB, keeps 5 files. Level via `RUST_LOG` (default `info`). In debug, also as text in the terminal.
- **Policy: never log** document text, passages, questions, answers, prompts, titles, file names or user paths. Identify documents by `document_id` and errors by type.
- **Safety net** (`nlmx-telemetry::redact`):
  - fields named `text`, `content`, `quote`, `query`, `question`, `answer`, `prompt`, `path`, `file`, `filename`, `title`… become `[redigido]` (redacted);
  - `/Users/`, `/Volumes/`, `/private/`, `/var/folders/`, `/tmp/` paths in messages become `<path>`;
  - free text is cut at 300 characters.
- The logs of `llama-server` itself (`logs/llama-server.log`) and of `fm serve` (`run/fm-serve.log`) are written by those processes. The real canary verifies that they contain no content.
