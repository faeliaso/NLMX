# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status

Implemented: app shell, design system, Apple FM status, SQLite persistence, PDFium document engine, the ingestion pipeline up to chunks (Documentos imports PDFs) embeddings + vector/lexical indexes, the Modelos screen (download with confirmation, progress, activate, remove, verify) the Chat (saved conversations; free conversation with Apple FM by default, or answers from the documents streamed with clickable citations) the PDF viewer beside the chat and the Indexação screen (index state, background work, retry/reindex). Multi-format import (PDF, Markdown, TXT, CSV, EPUB, DOCX, XLSX) with progress. Not yet: OCR. Design docs:
- `docs/README.md` — index of the docs below.
- `docs/PRODUCT.md` — product vision, requirements (RF01–RF29) with implementation status, measured targets, open risks, next steps.
- `docs/ARCHITECTURE.md` — current modules, ports, flows, process/model management, SQLite schema, packaging.
- `docs/adr/` — accepted decisions. Write a new ADR when changing any of them.
- `docs/DESIGN_SYSTEM.md` — tokens, components, states, accessibility rules.

## Commands

```sh
make bootstrap   # once: Tailwind CLI → tools/bin, HTMX 4 → ui/vendor, PDFium 7881 → runtime/lib, llama-server b11349 → runtime/llama
./scripts/fetch-embedding-model.sh  # Qwen3-Embedding-0.6B GGUF (~640 MB) → models/, plus models/embedding.json
make test-unit | test-integration   # subsets of `make test` (see docs/TESTING.md)
make dev         # cargo tauri dev in apps/desktop/src-tauri
make test        # cargo test --workspace
make lint        # cargo fmt --check + clippy -D warnings
# CI/release: .github/workflows (ci.yml, release.yml), see docs/CI.md; flow feature/* → develop → main, tag vX.Y.Z releases
make bundle      # dist/NLMX.dmg (Apple Silicon, ad-hoc signed) + scripts/verify-bundle.sh — see docs/RELEASE.md
make release     # same, Developer ID signed + notarized (APPLE_SIGNING_IDENTITY, APPLE_ID/APPLE_PASSWORD/APPLE_TEAM_ID)
./scripts/make-icons.sh  # app icons (icon.icns + PNGs) from apps/desktop/src-tauri/icons/source.png; needs ImageMagick
make acceptance  # installs dist/NLMX.dmg in a temp folder with a temp HOME: first launch, self-check, model download + checksum (~640 MB), offline RAG/chat/viewer with the app's runtime → target/acceptance/
cargo test -p nlmx-parser-text paragraphs  # single test: -p <crate> <name filter>
cargo test -p nlmx-workspace-tests         # architecture (dependency-rule) tests
cargo test -p nlmx-pdf-pdfium --test engine  # DocumentEngine against real PDFium + tests/fixtures
cargo run -p nlmx-pdf-pdfium --example generate_fixtures  # regenerate the hand-written fixture PDFs
```

Tailwind runs from `crates/ui-web/build.rs` into `OUT_DIR`; CSS and JS are embedded with `include_bytes!`, so editing templates, `ui/styles` or `ui/scripts` just needs a rebuild.

Debug builds only: `NLMX_START_PATH="/design-system?theme=dark"` sets the start page (design-system gallery, any section), useful for screenshots.

## Code architecture

Hexagonal Cargo workspace (ADR 0001):
`crates/domain` ← `crates/application` (use cases + all port traits in `application::ports`) ← `crates/adapters/*` and `crates/ui-web` ← `apps/desktop/src-tauri` (crate `nlmx-desktop`, composition root in `src/wiring.rs`).

- UI: askama templates live in `apps/desktop/ui/{pages,components}` (`crates/ui-web/askama.toml` points there); `ui-web::router()` is an axum `Router` that `src-tauri/src/protocol.rs` drives via `oneshot` for every `nlmx://localhost/...` request. The window is created in `setup` (no windows in `tauri.conf.json`); CSP is set as a response header in `ui-web`, not in `tauri.conf.json`.
- Navigation: sidebar links use `hx-get` + `hx-target="#content"` + `hx-push-url`. `ui-web::shell::page()` returns the section content plus an out-of-band `#sidebar-nav` for HTMX requests, and the full shell otherwise (first load, reload, history restore). New sections: add a `Section` variant and a template in `ui/pages/sections/`.
- Testing, metrics and logs: see `docs/TESTING.md`. Measurements go through `nlmx_application::telemetry::record(Measurement)` — `domain::telemetry::Measurement` holds only ids, counts, durations and fixed labels, so it cannot carry content; add a variant rather than logging numbers ad hoc. Logs are JSON lines in `<data>/logs/nlmx.jsonl` via `nlmx-telemetry` (installed in Tauri `setup`, which also starts the 60 s memory/storage sampler). **Never log document text, chunks, questions, answers, prompts, titles, file names or user paths** — identify documents by id; the redaction layer (sensitive field names → `[redigido]`, user paths → `<path>`) is a safety net; there is no automated privacy canary any more, so review log changes by hand. Shared workspace-test setup lives in `tests/tests/support/mod.rs`; `tests/golden/rag.json` is used only by `make acceptance`.
- PDF coordinates: PDFium reports page-space rects (bottom-left, unrotated); `layout::to_display_box` maps them into the displayed page (rotated by `/Rotate`, top-left origin), which is what rendering and the viewer use. Never call `PdfPageText::all()` — it is bounded by the rotated page size and misses text on rotated pages; use `worker::all_text`.
- HTMX 4 quirks: swap events (`htmx:after:swap`) fire on the element that triggered the request, not on the target — react to content changes (a `MutationObserver` on the target) instead of comparing `event.target.id`. During a swap's settle step, a new element with the same `id` as an old one temporarily receives **all the old element's attributes**; never keep runtime state in attributes of elements with an `id` inside swapped content (the viewer has no ids for this reason).
- Errors render as the design-system error state with the right status code; HTMX 4 swaps 4xx/5xx by default. Panics in handlers become a 500 in `protocol.rs`. Network/IPC failures surface as toasts from `ui/scripts/app.js`.
- Tauri commands (`src-tauri/src/commands.rs`) are only for native operations; they return `{ code, message }` errors and are invoked through `data-command` buttons. IPC works from the `nlmx://` origin (`withGlobalTauri: true`).
- Styling: never use raw colors or Tailwind `dark:` — only tokens from `ui/styles/tokens.css` (`light-dark()` values); see `docs/DESIGN_SYSTEM.md`.
- Persistence (`crates/adapters/store-sqlite`): the database is `~/Library/Application Support/dev.nlmx.desktop/nlmx.sqlite3`, opened and migrated in Tauri `setup` (`src-tauri/src/wiring.rs`); if it fails, the UI still starts and shows the error. Migrations live in `migrations/NNNN_name/{up,down}.sql`, registered in `src/migrations.rs` — always write a `down.sql`, use STRICT tables, ISO-8601 ms timestamps, `CHECK`ed status columns, and a `version`-bumping touch trigger on editable tables (see the header of `0001_app_settings/up.sql`). `cargo test -p nlmx-store-sqlite` checks reversibility, cascades and constraints. Multi-format (ADR 0013, migration 0011): additive only — never recreate `document_chunks` (FTS content table; the runtime `chunk_vectors_<id>_chunk_delete` triggers hang on it). `documents.format` + generated `previewable`; `document_sections` holds structure (no text); `chunk_provenance` holds each `save_processed` chunk's `SourceLocation`/metadata. A PDF chunk keeps its pages/bboxes in `document_chunks`; any other format stores the placeholder `page_start = page_end = 1` there (meaningless unless `format = 'pdf'`), so never read pages without checking the format. `DocumentRepository::save_processed`/`chunks_of`/`sections_of` are the multi-format API (`save_extraction` is still the PDF path in production). No `UPDATE` in a migration of existing rows (`documents_touch` bumps `version`).
- PDF (`crates/adapters/pdf-pdfium`): `DocumentEngine` port (`application::ports`) with domain types in `domain::document` — pages are 1-based, bounding boxes use a **top-left** origin in PDF points. `PdfiumDocumentEngine` runs every PDFium call on one worker thread (`src/worker.rs`); pure helpers (span grouping, PDF dates) live in `src/layout.rs`. The pdfium-render API feature (`pdfium_7881`) and the binary pinned in `scripts/bootstrap.sh` must stay on the same build. The dylib is found via `NLMX_PDFIUM_PATH`, then `Contents/Frameworks` (bundled by `tauri.conf.json`), then `runtime/lib` in debug. Known gap: pdfium-render 0.9.4 never returns `ModDate`, so `modified_at` is usually `None`.
- Multi-format indexing (ADR 0014): `DocumentIngestion.pipeline: Some(ContentPipeline)` is the production path — format from `DocumentType::from_path`, parser from `ParserRegistry` (no per-format `if`s), status `queued → extracting → structuring → chunking → embedding → indexed | failed | needs_ocr`, progress through the `ProgressSink` port (`IngestProgress`; Tauri adapter `ProgressRelay` emits `ingest-progress`, command `ingest_progress`; **file names go to the UI only, never to logs**; the Indexação screen no longer renders this progress — the event and command are kept without a UI consumer). `import_documents` only queues the picked files (`importer::ImportQueue`, one worker, one file at a time): `DocumentIngestion::enqueue` registers the document as `queued` (visible at once), `process` runs the pipeline in its own task; the app emits `documents-changed` (the UI debounces and reloads the list) and one `import-finished` toast per batch; a failure is a `Failed` document, never a crash. `reindex(id)` is idempotent; a changed file (same `original_path`, new hash) updates the same document via `find_by_original_path` + `replace_source`. The library stores `<sha>.<ext>`. `pipeline: None` is the legacy PDF-only path below (tests with fakes).
- Ingestion, legacy PDF path (`application::use_cases::DocumentIngestion`): `import(path)` hashes the file (SHA-256) → duplicate if known (a `failed`/unfinished one is retried instead) → copies it to `<data>/library/<sha>.<ext>` → `ingest(id)`: DocumentEngine → `StructureAnalyzer` (`structure-heuristic`: normalization, header/footer removal, headings → `section_path`, de-hyphenation, lists) → `Chunker` (`chunker-structural`: per-section target/max/overlap tokens, SHA-256 `content_hash`) → `DocumentRepository::save_extraction` replaces pages+chunks in one transaction. Nothing is written before that save, so re-running is idempotent; `resume()` runs at startup for documents left in queued/extracting/structuring/chunking. Without embeddings the document ends in status `embedding` with its job in `waiting_model`. Bump `structure_heuristic::VERSION` / `chunker_structural::VERSION` when their output changes.
- Notes (ADR 0018): "Adicionar nota" pastes text as a source of type `DocumentType::Note` — no file anywhere, the text lives in `documents.note_text` (migration 0014) and the regular pipeline does the rest (`DocumentIngestion::enqueue_note` → `NoteDocumentParser` over `DocumentSource::note(text)` → `SourceLocation::Note { start, end }` character range, label `<title> · caracteres a–b`). Never previewable: no viewer; the source panel hides Arquivo/Tamanho. `POST /documents/notes` hands the text to the `NoteSubmitter` port (`NoteInbox` → `ImportQueue::push_note` in `src-tauri`). Title comes from `domain::note::note_title`, text from `clean_note_text`; a note's `library_path` is empty and `original_path` NULL, so never assume a document has a file (check `note_text`/`DocumentType::is_note`). Tests: `tests/tests/note_integration.rs`.
- Parsers (ADR 0011, used by the multi-format ingestion, ADR 0014): port `DocumentParser` (`application::ports`) → `domain::parsed::ParsedDocument` (sections of typed `ContentBlock`s, each with a `domain::source::SourceLocation`; structure is kept until chunking). `ParserRegistry` picks the parser by `DocumentType` (extension/MIME). `PdfDocumentParser` (`application::services::parsing`) composes `DocumentEngine` + `StructureAnalyzer` and shares `read_layouts` with `DocumentIngestion`; Markdown/TXT/CSV are in `crates/adapters/parser-text`, EPUB in `crates/adapters/parser-epub`, DOCX and XLSX in `crates/adapters/parser-office` (ADR 0017: DOCX → `SourceLocation::Docx` heading path + paragraph, tables as one `Record` per row prefixed `Tabela N[ — legenda]: <colunas>` with `SourceLocation::Docx.table = N`, label = section path only; XLSX → one section per visible sheet of `Record` blocks, `SourceLocation::Xlsx` sheet + Excel row (label = sheet + rows of the chunk, e.g. "Clientes, linhas 2–3"; an Excel table, when present, gives the header), chunked per sheet by `RecordChunker::chunk_sheet`; neither has a viewer; migration 0013 replaces the `documents.format` CHECK by swapping the column, never recreating `documents`) (adapters never depend on each other, so the PDF parser cannot live in an adapter). Parsers must not log or put document content, names or paths in errors; every parser passes `nlmx_testing::document_parser_contract`. Only PDF is `DocumentType::previewable`; every format is indexable.
- Content pipeline (ADR 0012; `DocumentIngestion` runs it when its `pipeline` field is set, which `wiring.rs` always does): `ContentPipeline` (`application::services::pipeline`) runs parse → normalize (`DocumentNormalizer`, `normalizer-text`) → chunk (`DocumentChunker`, `MultiFormatChunker` in `chunker-structural`) and returns `ProcessedDocument`; embeddings are a separate stage over stored chunks and the pipeline must not mention them (`architecture.rs`). A `DocumentChunk` carries `document_id`, `chunk_id` (`None` until stored), `section_path`, `SourceLocation`, `ChunkMetadata`, `token_count`. One generic core chunks every format (`SourceLocation::merge`/`trailing` build the chunk location); `StructuralChunker` (PDF, in production) is a thin wrapper with output identical to the legacy algorithm — keep the equivalence tests passing and bump `VERSION` only when its output changes. The normalizer never changes block kinds or locations; PDF-specific cleanup stays in `structure-heuristic`.
- CSV (ADR 0011, "CSV semântico"): `CsvStream` (`parser-text`) streams records as `Registro N:\nColuna: valor` blocks (`Csv{row,row}` = data rows, header not counted) with `DatasetMetadata`; the header is verified, never assumed (`UncertainHeader`/`NoHeaderRow` warnings). `RecordChunker` (`chunker-structural`, lazy, not a port yet) turns records into `DocumentChunk`s with an `Arquivo/Colunas/Linhas` preamble, no overlap. `DocumentParser::parse` caps at 250k rows; the stream does not.
- Embeddings (`crates/adapters/embed-llama`): `LlamaServer` supervises the `llama-server` child (pidfile + key file in `<data>/run/`, log in `<data>/logs/llama-server.log`; an existing healthy server with the same binary and model is reused, a stale one replaced, and processes that are not our binary are never signalled). `LlamaCppEmbeddingProvider` implements `EmbeddingProvider`, starting the server on first use; the app stops it on `RunEvent::Exit`. It runs with `--cache-ram 0 --no-cache-prompt --parallel 1` (the default 8 GiB prompt cache grew it to ~10 GB) and stops itself after `idle_shutdown_secs` (45 s) without use; hold `LlamaServer::begin_use()` for any multi-request use so it is not stopped midway. The model is external config: `NLMX_EMBEDDING_CONFIG` or `<data>/embedding.json` (see `models/embedding.example.json`). Tests run against `src/bin/fake-llama-server.rs`; pass its behaviour switches via `LlamaServerConfig::extra_env`, never `std::env::set_var`.
- Runtime vs models: llama.cpp is part of the app — `scripts/stage-runtime.sh` (run by bootstrap and `make bundle`) stages `llama-server` as the Tauri sidecar (`bundle.externalBin` → `Contents/MacOS/llama-server`, rpath `@executable_path/../Frameworks`) and its dylibs + libpdfium into `bundle.macOS.frameworks` (`Contents/Frameworks`), so the bundler signs every Mach-O; `tauri-build` needs these staged files even for `cargo build`. Detected by `LlamaCppRuntime` (`InferenceRuntime`). `nlmx-desktop --self-check` verifies an installed app (PDFium, SQLite + sqlite-vec, sidecar) without a window or user data. GGUF models are downloaded on demand by `LocalModelProvider` (`crates/adapters/models-catalog`, port `ModelProvider`) from the embedded `catalog/models.json` into `<data>/models/<id>/<version>/`. **Never download without user confirmation**: `download` takes a `ConfirmedDownload`, which only `DownloadPlan::confirm()` creates — call it only from an explicit user action. `activate` writes `<data>/embedding.json` for the embedding provider; stop `llama-server` before removing/updating the active model. Catalog entries must pin the upstream revision in `version` and `url`, with verified `size`/`sha256`.
- Runtime wiring (`src-tauri/src/wiring.rs`): `EmbeddingSlot` (implements `EmbeddingSource`) holds the current `LlamaCppEmbeddingProvider` and is reloaded after model commands (`apply_model_change`: stops the old llama-server; re-embeds everything if the model changed, else only pending). `EmbedDocuments` runs right after ingestion and at startup (`embed_pending`); without a model documents stay in `embedding` and search is lexical-only. Model commands live in `commands.rs` and emit `model-download-progress` events; `download_model` is the only place that calls `DownloadPlan::confirm()` (triggered by the dialog's button). For a dev model without downloading: launch with `NLMX_EMBEDDING_CONFIG=$PWD/models/embedding.json`.
- Source provenance (ADR 0015): every `ChunkView`/`Passage`/`Source`/`Citation`/`MessageSource` carries a `SourceReference` (via `domain::source::RetrievedSource`: document, file name, type, chunk, relevance, `SourceLocation`, metadata) whatever the format; label is `"<file> · <location>"`. A PDF's prompt header keeps `paginas`/`secao`, other formats get `tipo`/`localizacao`; `[página N]`, `Citation::viewer_target` and `DocumentRef.pages` are PDF-only. The RAG only provides provenance — the UI decides (ADR 0016): every source and `[n]` is a button into the side panel `#viewer` — the PDF viewer for a PDF, `GET /sources/{id}[?cite={msg}-{n}]` (Informações da fonte) for any other format; there is no preview or generic viewer for those. Icon/label of a format come only from `ui-web::formats::format_view`; Documentos has `/chat?source={id}` ("Detalhes");  Indexação lists show the format icon and label per row. Scripts are plain JS (no TypeScript/Node/Lucide dependency; icons are SVGs in `ui/components/icons`). Never read `ChunkView.page_*` without checking `document_type`. Citations persist `document_type`/`document_name`/`locator` (migration 0012).
- RAG context: `application::services::retriever::Retriever` wraps `HybridRetriever` and returns `RetrievalContext { passages, documents }` — exact duplicates across documents removed (kept in `metadata.duplicates`), neighbouring chunks joined only within the same section (`domain::retrieval::join_adjacent` drops the chunker overlap), near-duplicates dropped (trigram Jaccard), `min_score`/`max_per_document`/Top-K applied. The Chat search uses it. Similarity helpers (`fold`, `coverage`, `jaccard_trigrams`, `same_content`) are pure functions in `domain::retrieval`.
- Chat (`application::use_cases::ChatService` + `ui-web/src/chat.rs`): `POST /chat/{id}/messages` saves the question and an assistant placeholder (`MessageStatus::Streaming`) and returns the turn; `app.js` sees `[data-answer][data-status=streaming]` and calls the Tauri command `answer_message({messageId, onEvent: Channel})`, which runs `ChatService::answer` and sends `{kind:"token"}` / `{kind:"done"}`; on `done` the JS swaps in `GET /chat/messages/{id}` (final HTML). `cancel_answer` trips the message's `CancelFlag` (partial answer kept). Model text is rendered by `ui-web/src/markdown.rs` (ADR 0020): `pulldown-cmark` events → allow-listed HTML (headings, lists, emphasis, quotes, code blocks (coloured by `highlight.rs`, an approximate dependency-free scanner), tables, `http`/`https`/`mailto` links, `<button class="citation">` for `[n]` that has a source); raw HTML is escaped, images dropped, and links never navigate the WebView (`open_external` command) — never render model output any other way. Copying an answer copies its stored Markdown. Citations `[n]` and page references `[página N]` open the viewer (below). Conversations, messages and every source given to the model (`citations.cited`) live in SQLite (`ConversationRepository`, migrations 0005 + 0007 + 0010).
- Free conversation (ADR 0009): `ConversationScope` is `Free` (default for new conversations) | `Library` | `Document(id)` — `conversations.mode` + `conversation_scopes`. Each assistant message stores its `AnswerGrounding` (`messages.grounding`) and `ChatService::answer` dispatches on it: `Documents` → `RagEngine`, `Free` → `services::free_chat::FreeChat`, which only gets the `LlmProvider` — never give it a retriever or chunk reader (isolation is by construction). Its prompt keeps fixed instructions in `system`, the neutralized earlier turns in `GenerationRequest::history` (sent to `fm serve` as real `user`/`assistant` messages — as text in the user turn the model echoed earlier answers) and the question in `user`, dropping the oldest turns until `count_tokens` fits. Changing the scope never rewrites earlier answers; `answer_freely` (`POST /chat/messages/{id}/free`, the "Responder sem os documentos" button) turns a `NotFound` document answer into a free one.
- PDF viewer (`application::use_cases::ViewDocument`, `ui-web/src/viewer.rs`, `ui/scripts/viewer.js`): everything goes through PDFium — no pdf.js. `GET /viewer/{doc}?page=N&cite={message}-{n}` (a source) or `&ref={message}-{page}` (a `[página N]`) renders into `#viewer` beside the chat log (resizable, full screen, Esc closes); `/chat?view={doc}` opens it from Documentos. Page sizes come from `document_pages` (`DocumentRepository::pages`), so the layout is known without opening the PDF; `viewer.js` loads page PNGs (`/documents/{id}/pages/{n}.png?w=` in width steps) and the text layer (`/viewer/{doc}/pages/{n}/text`, transparent spans scaled to their bbox for native selection) only for pages near the viewport. Search is `/viewer/{doc}/search?q=` (JSON, `domain::viewer::find_in_spans`: accent/case-insensitive, across spans and line-end hyphens); spans are cached per page in `ViewDocument`. All overlays are boxes in PDF points (top-left origin) converted to % of the page. `CitationEngine` resolves `[página N]` to the source covering the page (or the only document in context) and saves them as `message_page_refs` (migration 0008).
- Indexação (`application::use_cases::Indexing`, `ui-web/src/indexing.rs`): read-only port `IndexingReader::snapshot` (documents + latest ingest job + vectors of the active model). Actions are Tauri commands (`retry_document`, `retry_failed`, `embed_pending_now`, `reindex_all`) that claim `Indexing::begin()` (exclusive; `busy` otherwise), run in the background and emit `indexing-changed` when done. Other indexing work (imports, startup resume, `apply_model_change`) registers with `IndexingActivity::begin()` — keep doing so for new background indexing paths. The fragment polls (`every 2s`) only while work is running.
- Document removal (`application::use_cases::RemoveDocument`, ADR 0008): `DocumentRepository::remove` deletes, in one transaction, the conversations scoped to the document, the question + answer pairs in other conversations whose answer had a source or `[página N]` from it, conversations left empty, then the document (cascades do the rest). It is refused while the document is being read, deletes `<sha>.pdf`, and clears the viewer's span cache; `prune_library` at startup removes orphan library files. Connections use `PRAGMA secure_delete = ON` and the FTS5 table has `secure-delete` (migration 0009) — removed text must not stay in the database bytes (`removed_text_leaves_no_bytes_behind`). Ids can be reused, so page image URLs carry `v=<sha prefix>`; never key a cache by document id alone. Any new table holding document-derived data must be covered by `remove`.
- Question intents (`domain::rag_intent`): "Explique este documento." → `QueryIntent::Overview` (first chunk of each section of the single document in scope; asks to choose a document otherwise) and "seção N" → `Section(N)` (chunks whose section matches `section_matches`, incl. subsections); both skip the relevance gate. Follow-ups with history are rewritten into a standalone question by one short LLM call before searching.
- RAG Engine (`application::services::rag`): `RagEngine::ask` = Retriever → relevance gate (`min_relevance`; below it ⇒ `NotFound` without calling the model) → `ContextBuilder` (`rag/context.rs`, pure: token budget, dedupe, documents by relevance then pages, numbered `<trecho>` blocks) → exact `count_tokens` check (drops the weakest passage until it fits) → `LlmProvider::generate` (streams via `on_token`) → `CitationEngine` (`rag/citations.rs`, pure: `[n]` → document/chunk/pages/bboxes, invalid numbers removed). **Document text never goes into the `system` instructions** and is passed through `context::neutralize` (angle brackets → `‹ ›`, control chars removed) — keep both when changing the prompt.
- LLM (`crates/adapters/llm-fm`, port `LlmProvider`): `FoundationModelsProvider` wraps `/usr/bin/fm` (no Swift). Compatibility (macOS ≥ 27 via `kern.osproductversion`, native arm64 — Rosetta refused —, executable `fm`) is checked once at construction; incompatible ⇒ `LanguageModelStatus::Incompatible` and `fm` is never spawned. `status()` runs `fm available` (exit 69 ⇒ `LicenseRequired`; other messages classified into `UnavailableKind` by `errors::classify`) and caches it for `status_ttl` (30 s). Generation goes through `fm serve --socket` started lazily (socket `$TMPDIR/nlmx-fm-<pid>-<n>.sock`, ≤ 103 bytes, else `/tmp`; pidfile/log in `<data>/run/`; restarted if dead; one generation at a time; stopped on `RunEvent::Exit`), and falls back to `fm respond --stream -i <system> <user>` when the server can't start (for `serve_retry_after`, 5 min) or drops before answering. Every failure maps to `LlmError` in `src/errors.rs`. `fm serve` never rejects an oversized prompt (it degenerates), so budgets are enforced by the RAG.
- HTTP: the workspace `reqwest` has `default-features = false` (no TLS) because llama-server/fm are loopback/Unix-socket only; the model downloader enables `native-tls` (macOS Security framework). Any new https client must enable TLS too — `models-catalog` has a test asserting its client speaks https (its absence once broke every download while all tests, using local http servers, passed).
- Section questions ("seção N"): the section's chunks are complemented by the top search results, and a section with no matching heading falls back to the regular search (the structure analysis may drop numbered headings repeated at the same place on every page as running headers). Near-duplicate removal also requires `same_numbers` — templated passages that differ only in values are distinct.
- Hybrid retrieval: `application::services::retrieval::HybridRetriever` combines `VectorStore` (semantic) and `LexicalIndex` (FTS5 BM25, `store-sqlite/src/lexical.rs`) via the pure `domain::retrieval::fuse` (cosine clamped to [0,1] + min-max of −bm25 × squared query-term coverage, weighted). Filters (document/collection/page) are resolved by `ChunkReader::resolve`. Never put raw user text into an FTS5 `MATCH`: build a `LexicalQuery` (quotes every term). `Database` implements both `VectorStore` and `LexicalIndex`, whose `search` names collide — use `VectorStore::search(&db, …)` / `LexicalIndex::search(&db, …)` when both traits are in scope.
- Vectors (`VectorStore`, implemented on `Database` in `store-sqlite/src/vectors.rs`): one `chunk_vectors_<embedding_model_id>` vec0 table per `EmbeddingSpace` (model id + revision + dimension), created at runtime by `create_index` — never hard-code a dimension; build the space with `EmbeddingSpace::from_identity(provider.identity())`. The relation document → chunk → model → vector is `chunk_embeddings` (migration 0006, with the chunk's `content_hash` at embedding time) + the vec0 rowid = chunk id; inserts write both in one transaction, deleting a document/chunk removes both. vec0 KNN only accepts `ORDER BY distance` (ties are sorted in Rust); the `document_id IN (…)` metadata filter works on sqlite-vec 0.1.9. `src/vector.rs` holds the only `unsafe` in the workspace (`unsafe_code = "deny"`, allowed there for the FFI registration).
- `tests/tests/architecture.rs` enforces the rules below on the real `cargo metadata` graph — keep it passing when adding dependencies.

- `application` must not depend on infrastructure crates (rusqlite, pdfium-render, llama-cpp-2, tauri, hyper, axum, askama).
- Adapters never depend on each other; `ui-web` never depends on adapters or Tauri.
- No external types cross a port; adapters map to `domain` types and to per-port error enums.
- Only `app-tauri` instantiates adapters (DI via `Arc<dyn Port>`).
- `application` reports progress/streaming through the `EventSink` port, never by calling UI code.
- Every port has an in-memory fake and a reusable contract test suite in `crates/testing/`; new adapters must pass the same suite.

## What this is

NLMX: a local-first macOS desktop app (Tauri 2 + Rust) that imports PDFs, extracts/structures text with PDFium (`pdfium-render`), embeds chunks locally with llama.cpp + multilingual GGUF models, indexes in SQLite (FTS5 + sqlite-vec) for hybrid search (BM25 + KNN, weighted fusion — ADR 0007), and answers questions with citations using Apple Foundation Models.

## Hard constraints

- Target: **macOS 27+, Apple Silicon only**. Distributed as signed/notarized `.dmg`, not App Store.
- No Python, Ollama, Node, or remote server in the shipped runtime. Tailwind 4 is compiled at build time with the standalone CLI; HTMX 4 is vendored.
- Documents and queries never leave the device. The only network use is user-initiated model downloads.
- **No Swift in the project.** Generation goes through the system CLI `/usr/bin/fm`.
- **No TCP listeners**, with one exception: the supervised `llama-server` binds 127.0.0.1 only, on an ephemeral port, with a per-run API key (ADR 0006). UI ↔ Rust uses a Tauri custom URI scheme forwarding `http::Request` to the in-process axum router in `ui-web`; Rust ↔ `fm` uses a Unix socket.

## Apple Foundation Models via `fm` (verified on macOS 27.0.1)

- Run `fm serve --socket <path>` as a supervised child process; it exposes an OpenAI-compatible API: `GET /health`, `GET /v1/models`, `POST /v1/chat/completions` (SSE streaming with `"stream": true`, model id `system`).
- Unix socket paths are limited to 104 bytes — a longer path fails silently (server logs "listening" but requests return empty). Keep the socket path short and assert its length.
- `fm` exits with status **69** until the machine-wide license is accepted via `sudo fm license`. Check with `fm license --status`. The app must never accept it on the user's behalf.
- `fm count-tokens -q` gives exact token counts — use it to budget retrieved context. The context window is small; a ~6k-token prompt was accepted but produced degenerate output, so keep the context budget conservative until measured.
- Useful flags on `fm respond`: `--guardrails permissive-content-transformations`, `--schema`, `--tool ocr` with `--image`.

## Design rules that span components

- Custom-protocol responses don't stream; stream answer tokens to the WebView via Tauri Channels/Events.
- PDFium is not thread-safe: all PDFium calls go through one dedicated worker.
- vec0 tables have fixed dimensions: one vector table per embedding model; store model id/version with every vector and never mix embedding spaces.
- Ingestion is a persistent, resumable job queue (`jobs` table), transactional per document.
- Every document-mode answer must cite chunks by `[n]` mapped to document/page/bbox; low retrieval relevance must yield "not found" rather than a generated answer. Free answers have no sources and are always labelled as such (ADR 0009); the two modes never mix in one answer.
